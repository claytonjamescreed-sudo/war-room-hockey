# War Room — build plan

Two halves: a public season hub (no login) and a commissioner-only draft room, plus a public TV board. Backend is Lovable Cloud (database, one commissioner login, scheduled job). Everything NHL goes through our own server with short caching.

## 1. Database tables

```text
seasons          id '2026-27', nhl_season 20262027, season_games 84, count_from date (default 2026-09-29), swaps_per_team 2
pool_teams       id, season_id, slot 1-15, name                       (public read)
players          nhl_id PK, name, team, pos, last-season G/A/P/GP     (public read: safe columns only)
player_model     nhl_id, full players.json record (seasons, ESPN proj, ADP, injuries, linemates)  (commissioner only)
draft_picks      season_id, pick_no, round, slot, nhl_id, name, team, pos, preseason_proj, off_list flag  (public read)
roster_moves     season_id, date, slot, out_id, in_id, in_proj null   (public read) — All-Star swaps
daily_totals     season_id, date, slot, points, rank                   (public read) — written by the morning job
drafts           id, season_id, kind 'real'|'mock', order jsonb, order_locked_at, settings jsonb   (real: public read; mock: commissioner)
draft_board      draft_id, pick_no, slot, nhl_id / free-text name     (real: public read + realtime)
pool_habits      pool-teams.json leans per team                        (commissioner only)
contracts        contracts.json rows                                   (commissioner only)
warroom_prefs    stars, avoids, weights, market choice                 (commissioner only)
user_roles       user_id, role 'admin'  + has_role() function
```

All writes require `has_role(auth.uid(),'admin')`. Private tables have no public policy at all, so projections, odds, stars and avoids can't reach a public page even by accident. The draft-day projection shown under "projected finish" comes from `draft_picks`, which is already pool knowledge.

## 2. Backend functions

- **NHL relay** (server functions, plain User-Agent, in-memory + edge cache):
  - `getScoresToday` (score/now or score/{date}), 30 s
  - `getBoxscore(gameId)`, 30 s while live
  - `getGameLogs(ids[])`, 5 min, fetched 8 at a time as in season.js
  - `getNhlStandings` (team games played), 10 min; `getSchedule`, 10 min; `getLeaders`, 10 min
- **Season scoring** (`season.ts`, a faithful port of season.js): standings by date, swap rule, ties share rank, last night, last 7 days, projected finish (`(proj/84*20 + pts)/(20 + teamGP)`, 0.45 fallback). One server function `getStandings` returns the whole hub payload, cached ~2 min.
- **Live tonight** `getLiveTonight`: today's games + goal events filtered to pool players, mapped to owner, with each team's "still to play" count and tonight's points.
- **Morning job**: a public route `/api/public/cron/snapshot` protected by a shared secret header, called by a daily scheduled job at 12:45 UTC. It recomputes from game logs and upserts `daily_totals` for yesterday. A one-time backfill fills every date since count_from.
- **Commissioner functions** (login required + admin check): record/undo swap, rename team, change count_from, draft order set/randomize/lock/unlock, record/undo/fix pick, load War Room data.

## 3. Seeding the attached files

One migration creates the schema and inserts: the season row, 15 teams and 150 picks from `draft-2026-27.json`, the 666 players (safe columns into `players`, full record into `player_model`), `pool-teams.json` into `pool_habits`, `contracts.json` into `contracts`, and the 2026-27 draft as a locked "real" draft with its order and board. The large players file is inserted in chunks generated by a script from the upload. `engine.js`, `season.js`, `fetch-data.js` become code, not data (fetch-data stays reference only).

## 4. Pages and routes

Public (no login, server-rendered, own titles):
- `/` Standings + Live tonight panel (while games are on)
- `/race` race chart with team picker
- `/teams/$slot` team page (roster, tonight status, crossed-out drops, swaps left)
- `/leaders` pool scorers + best available
- `/rules` swap log + scoring rules in plain words
- `/tv` TV board (always dark); Draft-to and Undo only appear when the commissioner is signed in
- `/auth` commissioner sign-in (email + password; no public sign-up)

Commissioner only (behind the login gate):
- `/admin` swaps, team names, count_from
- `/draft` draft room: order and lock, pick entry, board grid
- `/draft/warroom` recommendations, star/avoid, weights, market choice
- `/draft/mock` mock drafts vs computer teams with end standings

The engine runs in the commissioner's browser on data loaded through an admin-only function, so none of its output is ever sent to a public page.

## 5. Live refresh during games

- Home page polls `getLiveTonight` every 60 s only while any game is PRE/LIVE/CRIT (every 10 min otherwise, stops when all FINAL/OFF).
- Server caches score/boxscore for 30 s, so 100 phones cost the NHL one call per 30 s.
- Tonight's points come from goal events in score/now (backed by boxscores for accuracy); standings re-rank on season points (games before today) + tonight.
- Ticker is built from goal events, newest first, with the owner's running total; it survives a reload because it's rebuilt from the day's events, not stored in the browser.
- Draft room / TV board sync via database realtime on `draft_board` and `drafts` — picks appear on the other screen within ~1 s.
